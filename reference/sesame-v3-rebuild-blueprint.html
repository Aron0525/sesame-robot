复现的定义

“能 build”不等于“机器人能对话”。

层次成功标准还不能证明什么

服务复现OpenClaw daemon 在回环地址运行，Gateway 读到完整非敏感配置并可通过 healthz。ESP32 已完成 TLS/WSS 握手。
设备复现ESP32 从 NVS 取得 Wi-Fi、设备 token 和根证书，能发现并认证 Gateway。云端 ASR、LLM、TTS 和扬声器都已验收。
端到端复现一次人工录音经过 ASR、OpenClaw、TTS 后由同一设备播放，并有中断和急停证据。长期稳定性、成本、家庭多设备或量产安全已解决。

REF—C

接口一：ESP32 和 Gateway

这是项目最重要的边界。复现时先固定合同，再写实现。

  1. Gateway 以 mDNS 服务 _sesame-gw._tcp.local. 广播 LAN 地址、端口、gateway_id、协议版本、TLS 标记和 /v1/device-stream 路径。
  2. ESP32 发现服务后，检查 advertised gateway_id、协议和 tls=1，用根证书校验 <mdns-hostname>.local。
  3. WebSocket Upgrade 携带每台设备独立的 Bearer token；连接后的第一帧必须是 sequence 为 0 的 session.hello。
  4. Gateway 把 device_id 映射到 token 和 user ID，拒绝 token 错误、Gateway ID 错误、重复活跃连接或不连续的控制序号。
  5. 双方随后交换 JSON 控制帧与带 32 字节 SSM1 头的 Opus 二进制帧。音频固定为 16 kHz、mono、20 ms、PCM S16LE 边界。
为什么要有 generation_id它把一轮录音和一轮 TTS 分开。用户中断后，旧 generation 的包不能继续被当作最新声音播放。
最小验收不接云端也可以验证：ESP32 完成 session.hello → session.ready，发送 listen.start、若干上行 Opus 包和 listen.stop。这证明网络、TLS、鉴权和二进制协议；不证明语义正确。
REF—D

接口二：Gateway、OpenClaw 和语音服务

Gateway 是唯一编排者，Provider 只是它调用的能力。

Opus packets ↓ decode PCM (16 kHz / mono / S16LE) ↓ DashScope ASR AsrResult(text, confidence) ↓ OpenClaw Adapter AgentResult(reply, voice, expression, actions) ↓ validate + action strip reply text + allowed voice ↓ DashScope TTS PCM ↓ encode Opus packets + response.plan

Gateway 在 app.py 的 _build_pipeline 创建 DashScope ASR、OpenClaw Agent 和 DashScope TTS，再把三者传给 ConversationPipeline。Pipeline 不该知道 token、WebSocket HTTP 细节或 GPIO；它只处理一轮输入如何变成一轮输出。

OpenClaw Adapter 使用回环地址，先做 challenge/connect，再发 chat.send。它为每段对话从 conversation_id 和本机 secret 派生 HMAC session key，避免把原始 DeviceID/UserID 发给 Agent。模型输出必须是项目 JSON Schema，而不是自由文本。

当前代码与部分文档存在的差异协议文档仍保留动作示例，但当前 openclaw/client.py 解析结果时设定 actions=()，app.py 发送 response.plan 前也把 action 固定为 None。复现当前代码时，模型不应触发物理动作；网页本地操作员控制是另一条通道。若要恢复 AI 动作，必须同时重做 Schema、Gateway、固件、测试和安全评审，不能改一行配置。
REF—E

设备端的运行分工

ESP-IDF 是框架，FreeRTOS 是并发运行时；它们不是另一套业务服务。

组件文件范围工程职责
启动组合main/app_main.cpp初始化网络、OLED、舵机、网页控制、音频和 VoiceController。
语音控制器components/sesame_voice/voice_controller.*录音、唤醒、预录音、TTS 播放、重连和会话状态。
音频sesame_audio/I2S 与 Opus；输入输出只保留内存帧。
网络sesame_transport/NVS 配置、Wi-Fi、mDNS、WSS 和 TLS。
协议sesame_protocol/SSM1 帧、控制事件、序号和回合状态机。
身体与 UIsesame_robot/、sesame_ui/、sesame_web/舵机白名单、动作执行、OLED 和独立的本地网页控制。

VoiceController 不是阻塞式录音函数。它创建语音任务和上行发送任务，并用有界队列隔离网络回调、上行帧和下行 TTS。这样 TLS 写入缓慢时，不会直接饿死 I2S 采样或 BOOT 按键处理。

REF—G

从零重建的正确顺序

每一步只证明一层，避免把硬件、凭据和云端问题混成一个故障。

  1. 克隆正式仓库，保留 firmware/esp32_voice_idf、gateway、contracts、docs、ops；不要复制旧 .venv、build 或整个 OpenClaw home。
  2. 新电脑安装 Python 3.12、uv、系统 libopus、Node.js 22/24、ESP-IDF v5.5.4、ESP32-S3 工具链和 Node 主机测试环境。
  3. 在 Gateway 执行依赖同步，构建或运行测试；在固件目录运行主机测试，再运行 ESP-IDF build。此时仍不需要硬件秘密。
  4. 安装固定版本的 OpenClaw，确认 daemon 只监听 127.0.0.1:18789。不要向 LAN 公开它。
  5. 由安全渠道创建 gateway/.env，再让 Gateway 校验配置并通过 healthz；准备 TLS 后才可启用实际设备连接。
  6. 生成私有 CA、网关证书和私钥。证书 DNS SAN 必须包含 mDNS hostname；启用 Gateway TLS 和 mDNS。
  7. 为每台 ESP32 生成独立 NVS，烧录固件与 NVS。固件本体与 NVS 分离，后者含秘密。
  8. 按“握手、上行音频、ASR、OpenClaw、TTS、播放、中断、本机急停”的顺序做联调，每一次失败只回到对应层排查。
