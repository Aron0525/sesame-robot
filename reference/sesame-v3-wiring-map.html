WIRE—C

音频：共用两根时钟，绝不能共用数据线

这是项目最容易接错的一组线。

ESP32-S3 INMP441 3V3 ───────────────→ VDD （目标低压数字电源） GND ───────────────→ GND GND ───────────────→ L/R （选 left slot；固件只读左声道） GPIO 14 ───────────────→ SCK/BCLK GPIO 47 ───────────────→ WS GPIO 48 ←─────────────── SD ESP32-S3 MAX98357A + speaker GPIO 14 ───────────────→ BCLK GPIO 47 ───────────────→ LRC/LRCLK GPIO 2 ───────────────→ DIN GPIO 1 ───────────────→ SD/EN GND ───────────────→ GND 电源轨 ───────────────→ VIN/VDD （当前项目未记录最终实际轨） OUT+ / OUT− ─────────────→ 扬声器两端；扬声器不是接 GND。

INMP441 与 MAX98357A 共享 BCLK 和 WS 是正确的：一个模块只输出自己的 SD 到 GPIO48，另一个模块只接收 GPIO2 的 DIN。固件在 16 kHz、32-bit stereo I2S 总线上工作，麦克风从左声道取样，播放时把单声道样本复制到左右 slot。

这里的“3V3 / 电源轨”是目标，不是已实测线色项目电源图明确把 INMP441 放在 3V3 数字域；但没有保存实物照片来证明你当前模块的 VDD/GND 究竟接到了哪一个排针。MAX98357A 的最终供电轨更被硬件文档明确标为“仍需按实物补录”。MAX98357A 芯片可在 2.5–5.5 V 单电源工作，并以 BCLK、LRCLK、DIN 接收 I2S；但你手中 breakout 的 VIN、GAIN、SD 标注和接法必须以实物丝印为准。[MAX98357A 官方资料](https://www.analog.com/en/products/max98357a.html)
WIRE—D

电源：信号线与供电线必须分开理解

ESP32 的 GPIO 只发控制信号；它不应该承担八个舵机的电流。

记录中的目标电源树： 7.4 V 电池 或 USB-C PD → LTC4416 电源选择 → VSYS ├→ SY8120B1 → 3V3 → ESP32 / INMP441 / OLED └→ TPS54531 → 5V_SERVO → 八个舵机 V+ 所有低压模块的 GND 与 ESP32 GND 必须共地。 舵机的 V+ 来自 5V_SERVO；舵机 signal 仅分别来自 GPIO 4/5/6/7/10/11/12/13。

硬件清单描述 Distro V3 用 TPS54531 从 VSYS 产生 5V_SERVO，典型计算值约 5.76 V。正式固件 README 说“独立 5–6 V 舵机电源、禁止 USB 给八路舵机供电”。这两句并不必然冲突：板载 5V_SERVO 可以是独立高电流轨，但前提是它由合格的电池或 USB-C PD 经 VSYS 供电，而不是只靠 ESP32 的 USB Serial/JTAG 线。

尚未确认的关键事实仓库没有证明当前 7.4 V 电池、USB-C PD、LTC4416、TPS54531 和每个舵机的红/棕线已经实际连通。更没有证明 5.76 V 在带载时稳定。不要把“代码使用八路 PWM”误读为“八个 SG90S 同时堵转安全”。
WIRE—E

八个 SG90S：每个都有三条线

杜邦线最常见的错误是只追信号线，漏掉共地或把供电接到 ESP32。

舵机端线目标去向项目意义
Signal（通常黄/橙，实际以你的线束为准）S0..S7 对应 GPIO 4, 5, 6, 7, 10, 11, 12, 13。只传 50 Hz PWM 控制信号。
V+（通常红）5V_SERVO 正电源轨。供给舵机电机电流，不能接 ESP32 的 3V3，也不应由普通 USB 供电。
GND（通常棕/黑）舵机电源地，并与 ESP32 GND 共地。没有共地，PWM 的电压参考不存在，舵机可能抖动、失控或完全不响应。

固件启动时把 8 路 PWM duty 设为 0，并调用 release_all()，因此正常上电不应自动把机器人摆到某个姿势。网页动作或本地操作者控制才会申请 PWM 所有权；STOP ALL 会释放这些输出。

WIRE—F

对着实物核对的安全顺序

这不是上电测试顺序；是先断电目测、再最小化上电的顺序。

  1. 断开舵机高电流电源，只保留 USB 数据线；拍一张 ESP32 与 Distro V3 正反面清晰照片。
  2. 只核 INMP441：VDD、GND、L/R→GND、GPIO14/47/48；确认没有把 SD 接到 GPIO2。
  3. 核 OLED：GND、低压 VCC、GPIO8 SDA、GPIO9 SCL；不要仅因模块能接受 5 V 就把 I²C 上拉到 5 V。
  4. 核每个舵机的三线：S0–S7 信号顺序、统一 V+、统一 GND、ESP32 与舵机地共地。
  5. 最后才装 MAX98357A 和扬声器：先确认 breakout 丝印和电源轨，再接 BCLK/LRC/DIN/EN；扬声器两端只接 OUT+/OUT−。
  6. 确认所有线无误后，再单独接入舵机供电；先测试 STOP，再测试单舵机小角度，而不是直接运行走路动作。
为什么 GPIO14/47 可以同时接麦克风和功放？

它们是由 ESP32 输出的 I2S 时钟，多个从设备可以监听同一时钟。数据线不能这样共享：INMP441 的 SD 是输入到 ESP32，MAX98357A 的 DIN 是从 ESP32 输出。

为什么舵机能有独立 5V 供电，却还必须和 ESP32 共地？

PWM 是相对地的电压信号。两边没有共同参考，舵机无法可靠判定 GPIO 的高低电平。
