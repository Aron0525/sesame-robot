第一课 · 心智模型

网关的本质与网络基础

先不背产品名。我们从“边界、代理、策略”三个词出发，把家庭路由器、Nginx、API Gateway 和 AI Gateway 放进同一个模型。

约 25 分钟15 个概念4 个练习
01—A

一个能覆盖所有网关的定义

先抓住不随产品变化的本质，再理解不同形态。

本课总纲

网关是位于两个通信域边界上的中介节点。它代表一侧接收通信，按照统一策略决定拒绝、转换、路由或转发，再把通信交给另一侧。

Concept 01

通信域（Communication Domain）

一组遵守相近规则、能直接通信的参与者。公网与公司内网是两个通信域；用户应用与模型供应商也可以看成两个通信域。

通俗解释像两栋门禁规则不同的办公楼。楼内可以自由走动，跨楼则必须经过门口。
Concept 02

边界（Boundary）

两个通信域相接的位置。边界意味着信任、协议、地址或管理责任发生变化。

案例浏览器属于不可信公网，订单服务属于私有网络；公网入口就是安全边界。
Concept 03

代理（Proxy）

调用者不直接接触真实处理者，而由中间节点代表一方完成通信。网关通常具有代理性质。

通俗解释你不直接进入仓库取货，而是把取货单交给窗口，窗口人员替你到仓库办理。
Concept 04

策略（Policy）

网关处理通信时执行的规则，例如谁能进、每分钟能进几次、请求应送到哪里。

案例“普通用户每分钟最多调用聊天接口 20 次”就是一条网关策略。
Concept 05

网关是一种角色，不是一种固定产品

路由器、Nginx、Envoy、Kong、AWS API Gateway 都可能扮演网关。判断依据不是软件名，而是它在当前架构中是否位于边界、代理通信并执行统一策略。

案例同一台 Nginx 在博客系统里可能只是静态 Web Server；在微服务前面接收全部 API 请求时，它就在扮演网关。
01—B

描述流量时必须掌握的语言

这些词会贯穿后面四课。

Concept 06

下游（Downstream）与上游（Upstream）

连接到网关、发起请求的一侧叫下游；接收网关转发请求的一侧叫上游。它们是相对于当前代理而言的。

案例浏览器 → Nginx → FastAPI。对 Nginx 而言，浏览器是下游，FastAPI 是上游。
Concept 07

入口（Ingress）与出口（Egress）

Ingress 表示流量进入一个受管理区域；Egress 表示流量离开该区域。它们描述方向，不必然指某个产品。

案例用户访问集群是 Ingress；Agent 从集群调用外部搜索 API 是 Egress。
Concept 08

数据包、连接与请求

数据包是网络层传输单元；TCP 连接是一段可靠通信通道；HTTP 请求是在连接上承载的应用消息。不同网关处理的对象不同。

通俗解释数据包像一辆辆货车，连接像固定运输线路，请求像一张完整订单。
Concept 09

端点（Endpoint）

可以被访问的具体网络位置，通常由 IP、端口或 URL 表示。一个服务可能有多个实例，也就有多个端点。

案例订单服务有三个实例：10.0.1.8:8000、10.0.1.9:8000、10.0.1.10:8000。
下游客户端 网关 上游服务 Browser ── HTTP Request ──▶ Listener ── Route ──▶ Endpoint 进入（Ingress） 真实处理者
01—C

L3、L4、L7：网关到底看得多深

层次决定网关可以根据什么信息做决策。

层次网关能看见典型决策案例
L3 网络层源/目标 IP、数据包下一跳路由把去公网的数据包交给家庭路由器
L4 传输层TCP/UDP、IP、端口、连接连接分发把 443 端口的新连接分给一台服务器
L7 应用层HTTP 路径、方法、Header、身份API 路由与治理/orders 去订单服务，/chat 去 Agent 服务
Concept 10

网络层网关（L3 Gateway）

根据 IP 路由表决定数据包的下一跳，不理解订单、用户或 HTTP 路径。

案例电脑发现目标 IP 不在本地网段，于是把数据包发给默认网关 192.168.1.1。
Concept 11

传输层网关或四层代理

根据 IP、端口和连接状态转发 TCP/UDP 流量，性能高，但通常不知道 HTTP 路径。

案例云负载均衡器把所有到 443 端口的 TCP 连接分给四台 Nginx。
Concept 12

应用层网关（L7 Gateway）

理解 HTTP、gRPC、WebSocket 等应用协议，因此能依据路径、方法、Header、Cookie、用户身份和消息内容做决策。

案例GET /products 可公开访问；POST /admin/products 必须是管理员，并且每分钟最多 30 次。
01—D

默认网关、路由器、NAT 与防火墙

这些词经常与“网关”一起出现，但并不等同。

Concept 13

默认网关（Default Gateway）

主机找不到更具体路由时，把数据包交给的默认下一跳。

通俗解释你不知道某个快递的专用通道时，就统一先交给小区大门的快递站。
Concept 14

路由与下一跳（Route / Next Hop）

路由表把目标网段映射到下一跳或网络接口。网关通常根据路由表转发，但“路由器”强调转发网络包，“网关”强调跨边界角色。

案例10.0.0.0/8 走公司 VPN；其他目标走家庭默认网关。
Concept 15

NAT（网络地址转换）

把内部私有地址转换成公网地址。家庭路由器常同时提供默认网关、NAT、防火墙和 Wi-Fi，所以这些概念容易被混为一谈。

案例家中三台设备使用不同私有 IP，却通过路由器的同一个公网 IP 访问互联网。
Adjacent Concept

防火墙与 DNS 不是网关的同义词

防火墙的核心是允许或阻止流量；DNS 的核心是名称解析。它们可以与网关集成，但职责不同。

案例DNS 把 api.example.com 解析到网关 IP；防火墙只允许 443；网关再把请求路由到订单服务。
01—E

识别任何网关的四步法

以后看到陌生产品，不要先看功能表，先问下面四个问题。

  1. 它位于哪两个通信域之间？
  2. 它代表哪一侧接收或发起通信？
  3. 它处理的是数据包、连接，还是应用请求？
  4. 它执行哪些公共策略，又有哪些业务规则不应放进去？
综合案例“Agent 应用通过一个组件调用 OpenAI 和本地模型。”边界是应用与模型供应商；组件代表应用发起请求；处理对象是 L7 模型 API；公共策略包括密钥隔离、模型路由和成本统计——因此它是 AI Gateway。
01—F

检索练习

先自己回答，再展开答案。主动回忆比重复阅读更容易形成长期记忆。

1. DNS 把域名解析成 IP，所以 DNS 就是网关吗？

不是。DNS 的核心职责是名称解析；它可以把域名指向网关，但通常不代理后续请求。

2. 为什么说“网关是一种角色”比“网关是一种软件”更准确？

同一软件在不同部署中可能承担不同职责；是否是网关取决于它是否位于边界、代理通信并执行策略。

3. L4 网关为什么不能按 /orders 和 /chat 分流？

因为它通常只理解连接、IP 和端口，不解析 HTTP 路径等 L7 信息。

4. 浏览器 → Nginx → FastAPI 中，谁是上游？

相对于 Nginx，FastAPI 是上游，浏览器是下游。
