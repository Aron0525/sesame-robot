v1.5 项目地图

读代码前先分清：哪些是正式程序，哪些是合同、工具、配置或本机运行状态。

REF—A

唯一正式运行链路

这是一条链路，不是三套彼此独立的软件。

用户语音 ↓ ESP32-S3 固件 ── WSS + Opus ──→ 电脑 Voice Gateway ↑ │ └──────── WSS + Opus + 表情 ────────────┤ ├─ PCM → DashScope ASR ├─ 最终文本 → 本机 OpenClaw └─ 回复文字 → DashScope TTS
REF—B

正式目录与入口

先从入口读，不从文件数量最多的目录读。

位置它是什么优先入口
firmware/esp32_voice_idf/唯一正式 ESP32-S3 固件；C++/ESP-IDFmain/app_main.cpp
gateway/电脑端 Voice Gateway；Python/FastAPIapps/voice_gateway/src/.../app.py
contracts/两端交换消息的合同；不是可单独启动的程序protocols/esp32-voice-gateway.md
ops/openclaw/固定 OpenClaw 版本的安装入口；不是 Agent 业务代码README.md
docs/架构、部署、硬件和安全说明；用于理解与操作project-overview.md
不作为正式运行基线endpoint-gateway/、output/、training/、.venv/、build/ 和 managed_components/ 是遗留、本机输出、训练材料或可重建产物。不要把它们当成主程序入口。
REF—C

三个层的最小职责

每一层都只做自己该做的事。

层接收产出绝不应负责
ESP32 固件麦克风、按键、网关命令Opus 音频、播放、OLED、经校验的动作调用 LLM、保存云端密钥
Voice Gateway设备 WSS、DashScope、OpenClaw 结果一轮受验证的语音回复让模型直接碰 GPIO 或任意舵机角度
OpenClawGateway 已确认的文本和能力清单受限 JSON：回复、音色、表情接收原始音频、设备 token、TLS 私钥
REF—D

判断一个文件是否重要

用四个问题，不需要猜作者意图。

  1. 它会被构建、启动或导入吗？若会，查入口和 CMakeLists.txt/pyproject.toml。
  2. 它在运行链路哪一段读数据、写数据或做验证？
  3. 失败时它会拒绝、重试、停止还是悄悄跳过？
  4. 它是否存放秘密或生成物？若是，通常不应进入 Git。
