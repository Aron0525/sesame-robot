# ESP32-S3 说话人验证实施计划

> 状态：已获产品确认，待实现。

## 目标

在主项目的 MultiNet 口令“你好，芝麻”命中后，用本机保存的 19 条用户录音生成模板并执行本地说话人验证；仅两者都通过才播放“我在”并进入录音。BOOT 按键仍直接开始录音，不经过声纹判断。

这不是安全级声纹认证：ESP32-S3 没有当前 Espressif 官方支持的声纹验证神经网络。实现使用同一段固定口令的本地声学模板相似度，旨在降低他人说出口令造成的误唤醒；不能防录音回放或合成语音。

## 架构

```text
MIC PCM (16 kHz, 20 ms)
  -> MultiNet "ni hao zhi ma"
  -> SpeakerVerification (最近 1.5 秒环形缓存 -> 特征 -> 余弦相似度)
  -> 通过：本地“我在” -> 原有 3 秒 VAD 等待
  -> 拒绝：静默清理 -> 待机

BOOT -> 原有手动录音路径（绕过 SpeakerVerification）
```

## 实施步骤

1. 新增纯 C++ `SpeakerVerification`：保存 1.5 秒 PCM、抽取稳定的时频统计特征、计算模板余弦相似度；无模板时失败关闭。
2. 先新增主机单测，验证环形采样、通过模板、拒绝噪声/短音频和关闭时拒绝；执行并确认红灯。
3. 实现模块直到单测通过；加入主机测试脚本。
4. 新增本地训练脚本：读取 19 条 WAV，用与设备相同的特征产生私有模板头文件；模板文件被 Git 忽略，不上传。
5. 在 `VoiceController` 中仅在 idle 的 wake 监听时向声纹门控喂 PCM；MultiNet 命中后先校验再开始提示。BOOT 保持绕过。
6. 新增源码策略测试，验证“口令 + 声纹”以及“BOOT 绕过”路径。
7. 运行训练、主机测试、ESP-IDF 构建；记录模板样本数与校准分数。只产出待烧录固件，不连接或烧录设备。

## 验收

- 当前“你好，芝麻”继续是唯一语音口令。
- 模板缺失、短音频、低相似度均不唤醒也不播放提示。
- 成功口令和已注册模板才进入既有 wake acknowledgement。
- BOOT 仍可在待机时直接录音。
- 生物模板和原始样本均保持本地、Git 忽略。
