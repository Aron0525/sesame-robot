第二课 · 流量工程

代理、TLS 与负载均衡

网关怎样接住请求、识别目标、选择实例并安全转发？这一课拆开真正的数据面零件。

约 35 分钟24 个概念5 个练习
02—A

代理家族：它到底代表谁

正向和反向的关键不是箭头方向，而是代理站在哪一方。

Concept 01

正向代理（Forward Proxy）

代表客户端访问外部服务。外部服务看见的是代理，而不一定看见真实客户端。

案例公司电脑先访问企业代理，代理再访问互联网，用于出口审计与访问控制。
Concept 02

反向代理（Reverse Proxy）

代表后端服务接收客户端请求。客户端只知道代理地址，不知道真实服务实例。

案例用户访问 api.example.com，Nginx 再把请求转给内网 FastAPI。
Concept 03

透明代理（Transparent Proxy）

流量被网络规则自动截获，调用方不必显式配置代理地址。

通俗解释普通代理像主动去服务窗口；透明代理像道路上的自动检查站，车辆自然会经过。
Concept 04

边缘代理（Edge Proxy）

部署在最接近外部用户的系统边缘，通常负责 TLS、WAF、缓存和公网入口。

案例全球用户先到最近的 CDN 边缘节点，再进入区域 API 网关。
正向代理：客户端 ──▶ 代理 ──▶ 互联网 代理代表客户端 反向代理：客户端 ──▶ 代理 ──▶ 后端服务 代理代表服务端
02—B

反向代理内部的五个零件

理解这些词，就能读懂 Nginx、Envoy、Kong 等大量配置。

Concept 05

Listener（监听器）

代理接收连接的网络位置，通常包含 IP、端口和协议。

案例网关在 0.0.0.0:443 监听 HTTPS，在 :80 把 HTTP 重定向到 HTTPS。
Concept 06

Virtual Host（虚拟主机）

同一个 IP 和端口根据域名承载多个站点或 API。

案例api.example.com 和 admin.example.com 都到同一网关，但匹配不同规则。
Concept 07

Route（路由）

把匹配条件映射到处理动作或上游目标。条件可以包含 Host、路径、方法、Header、查询参数。

案例POST /v1/chat 路由到 Agent 集群，GET /assets/* 路由到对象存储。
Concept 08

Upstream / Cluster（上游集群）

提供相同逻辑能力的一组后端端点。代理会在组内选择一个实例。

案例order-cluster 包含三个订单服务 Pod，任何一个都能处理订单查询。
Concept 09

Filter / Middleware（过滤器或中间件）

请求经过路由前后执行的一段公共处理逻辑，例如认证、压缩、改写 Header、记录日志。

通俗解释Listener 是大楼入口，Route 是楼层指示牌，Cluster 是目标部门，Filter 是沿途经过的安检、登记和消毒步骤。
02—C

请求到网关之前：DNS、CDN 与 WAF

它们经常排成一条链，但解决的问题不同。

Concept 10

DNS（域名系统）

把域名解析成 IP 或另一个域名。DNS 通常负责“找到入口”，而不是处理进入后的请求。

案例api.example.com 解析到云负载均衡器；后续 HTTP 请求才进入网关。
Concept 11

CDN（内容分发网络）

把可缓存内容放到离用户更近的边缘节点，减少延迟和源站压力。

案例机器人表情图片直接由附近 CDN 返回，不必每次回到主服务器。
Concept 12

WAF（Web 应用防火墙）

根据 Web 攻击特征或安全规则阻断恶意 HTTP 请求。

案例请求参数含明显 SQL 注入片段时，WAF 在到达 API 网关前直接拒绝。
Concept 13

DDoS 防护

吸收或清洗大规模恶意流量，重点是网络容量与攻击流量识别，不等同于普通 API 限流。

案例百万级伪造请求先被云边缘清洗，避免网关带宽耗尽。
用户 │ DNS：找到入口 ▼ CDN / DDoS：边缘缓存与大流量防护 ▼ WAF：识别 Web 攻击 ▼ API Gateway：身份、路由、配额 ▼ 业务服务
02—D

TLS：加密连接在哪里结束

HTTPS 不只是“有个证书”，还涉及信任边界如何划分。

Concept 14

TLS Termination（TLS 终止）

网关完成证书握手和解密，再把明文或重新加密后的请求发给上游。

案例用户与网关使用 HTTPS；网关和同一私有网络的 FastAPI 使用 HTTP。
Concept 15

TLS Passthrough（TLS 透传）

网关只转发加密连接，不解密内容，因此看不到 HTTP 路径。

案例银行要求证书和解密必须发生在核心服务，前置四层网关只按端口转发。
Concept 16

Re-encryption（重新加密）

客户端到网关是一段 TLS，网关到上游又建立另一段 TLS。

案例网关需要读取路径做路由，但公司政策要求内部网络也不能传明文。
Concept 17

mTLS（双向 TLS）

双方都出示并验证证书，不只是客户端验证服务端。常用于服务身份认证。

通俗解释普通 HTTPS 像顾客检查银行执照；mTLS 像银行也检查顾客的工作证。
02—E

负载均衡：选哪一个实例

路由先选“哪个服务”，负载均衡再选“该服务的哪个实例”。

Concept 18

Round Robin（轮询）

按顺序把请求分给各实例，简单且适合处理能力接近的无状态服务。

案例请求依次去 A、B、C、A、B、C。
Concept 19

Weighted Routing（加权分配）

不同实例或版本得到不同比例的流量。

案例新版本先接 10% 流量，旧版本继续接 90%，观察错误率后再扩大。
Concept 20

Least Connections（最少连接）

优先选择当前活跃连接较少的实例，适合请求时长差异较大的场景。

案例文件上传可能持续几十秒，不能只按请求数量平均分配。
Concept 21

Consistent Hash（一致性哈希）

根据用户、会话或某个键稳定选择实例，节点变化时尽量少改变映射。

案例相同会话 ID 尽量路由到同一个实时对话实例，减少本地缓存失效。
Related Concept

Sticky Session（会话黏性）

同一用户持续访问同一实例。它能兼容本地会话状态，但会导致负载不均和扩容困难；更稳妥的方式通常是把状态放到 Redis、数据库或专门状态服务。

案例实例 A 重启后，保存在其内存中的购物车消失。问题根源不是负载均衡，而是状态只存在单机。
02—F

服务发现、健康检查与故障转移

知道实例地址还不够，还要知道它现在是否能接请求。

Concept 22

Service Discovery（服务发现）

动态获得服务实例列表。来源可以是静态配置、DNS、Kubernetes、Consul 或控制面。

案例Kubernetes 中订单 Pod 扩容后，网关自动发现新端点，不需要人工改 IP。
Concept 23

主动健康检查

网关定期请求专用健康端点，根据结果决定实例是否可接流量。

案例每 5 秒访问一次 /health/ready，连续失败三次便暂时摘除实例。
Concept 24

被动健康检查 / 异常实例剔除

根据真实业务请求的连接失败、超时和 5xx 比率判断实例异常。

案例实例 B 的真实请求连续超时，即使健康端点还能返回 200，也应临时降低其流量。
Concept 25

Failover（故障转移）

主实例、主区域或主服务不可用时，把流量切到备用目标。

案例美国西部区域故障后，DNS 或全局负载均衡把用户切到东部区域。
边界提醒“进程活着”不等于“服务可用”。Liveness 检查是否需要重启，Readiness 检查是否应该接收流量；两者不应混为一谈。
02—G

缓存、压缩与协议转换

网关还能减少重复工作，但优化必须服从正确性。

Knowledge Point

Response Cache（响应缓存）

对相同请求复用已有响应，降低上游负载。必须正确处理缓存键、过期时间和用户隔离。

反例只按 URL 缓存 /me，可能把张三的个人信息返回给李四。
Knowledge Point

Compression（压缩）

使用 gzip 或 Brotli 减少响应体积，以 CPU 换带宽。

案例大型 JSON 从 500 KB 压到 70 KB，移动端下载更快。
Knowledge Point

Protocol Translation（协议转换）

在边界两侧使用不同协议时进行翻译。

案例外部客户端使用 REST/JSON，网关把请求转换为内部 gRPC 调用。
Knowledge Point

Request / Response Transformation（报文转换）

改写路径、Header 或轻量字段格式，以适配不同接口。

边界把 /old/users 改成 /v2/users可以；在网关里计算复杂订单价格不合适。
02—H

检索练习

用真实流量问题检验理解。

1. 路由与负载均衡有什么区别？

路由通常先确定逻辑服务或处理规则；负载均衡再从该服务的一组实例中选择具体目标。

2. 为什么 TLS 透传后通常不能按 HTTP 路径路由？

路径仍在加密内容里，四层代理看不到；除非它终止 TLS 或使用协议暴露的有限元数据。

3. 健康端点返回 200，真实请求却持续超时，应该补什么能力？

被动健康检查或异常实例剔除，用真实流量结果补充主动探测。

4. CDN、WAF、API Gateway 各解决什么问题？

CDN 侧重边缘缓存，WAF 侧重 Web 攻击防护，API Gateway 侧重 API 入口、身份、路由与治理。

5. 为什么 Sticky Session 不是保存业务状态的理想方案？

它让状态依赖单个实例，导致故障恢复、扩容和负载均衡变难；共享状态存储通常更稳。
