MAP—C

app_main()：启动顺序本身就是设计

文件：firmware/esp32_voice_idf/main/app_main.cpp。

  1. initArduino()：正式固件仍复用部分 Arduino 兼容动作代码。
  2. 初始化 esp_netif 和默认事件循环，给 Wi‑Fi 和本地网页共用。
  3. 初始化 OLED；失败只警告，所以无屏幕时其他模块仍可继续。
  4. 初始化舵机 PWM；失败直接返回，因为机器人输出端没有可靠基础。
  5. 启动本地 WebControlServer；语音失败时也尽量保留手动控制。
  6. 初始化 AudioHal；失败时网页仍在，语音停止。
  7. 启动 VoiceController；它才创建语音任务、队列并加载 NVS。

static 在这里是什么意思

static AudioHal audio、static VoiceController voice 表示这些对象在 app_main() 返回后仍然有效，直到设备重启。FreeRTOS 任务持有它们的地址；若是普通局部变量，函数返回后任务会访问悬空内存。

MAP—D

VoiceController：语音总调度器

精读顺序：头文件字段 → start() → run() → start_listening() → capture_and_send()。

字段/结构通俗解释工程目的
session_id_ / turn_id_“这条连接是谁”与“这句话是哪一轮”。让断线、取消、迟到消息精确归属。
TurnStateMachineIdle / Listening / Thinking / Speaking。禁止矛盾组合，例如一边播放一边当作普通空闲录音。
CaptureSession录音是否正在进行，来源是按键、唤醒词还是追问。BOOT 与唤醒词共享一条生命周期，而非两个易冲突的布尔值。
WakeVadEngine端侧唤醒词和 VAD（语音活动检测）。决定自然语音何时开始/结束，不等于云端 ASR。
PcmPreRollBuffer最近 500 ms、25 帧 PCM 的环形缓冲。补偿 VAD 判定延迟，避免吞掉第一个音节。
三条 queue下行音频、Gateway 控制回调、上行待发送帧。网络、音频和控制互不挤占；对端洪泛也有上限。
VoiceController::run() 的一轮循环 取 Gateway 控制事件 → 处理断线/重连 → 读 GPIO0 去抖按键 → 判断是否武装唤醒词 → 读 20 ms I2S PCM → 预录缓存 / VAD / 上行编码 → 下行 Opus 解码播放 → TTS 收尾

ESP32-S3 在 ESP-IDF 中以双核 FreeRTOS 运行。项目把不同延迟特征的工作显式拆开。

任务名创建位置亲和性 / 优先级主要工作

MAP—H

最关键的两个数据结构

控制 JSON 与音频二进制包各自解决不同问题。

ControlEvent

有业务含义的控制帧

固定字段：v、type、session_id、turn_id、request_id、sequence、timestamp_ms、payload。

listen.start 的意思是“开始允许收这一轮音频”；它本身不是音频。

AudioFrame

可排序的声音包

固定 32-byte 头：SSM1、版本、方向、flags、stream ID、generation、sequence、时间戳、payload 长度，之后才是至多 1,500 bytes 的 Opus。

generation 分开不同回合；sequence 找同一回合内部的丢包和乱序。

当前 AI 的动作权限动作白名单和机器人动作类仍存在，用于本地操作员控制和兼容；但当前 openclaw/client.py 把 Agent 的 actions 设为空，app.py 下发前又固定 action = None。因此当前 AI 回复不能让物理舵机动作。

配置不是源码：具体到文件

排错时先分清“需要重新生成的秘密”与“可以修改并提交的实现”。

文件/产物是否应提交读/写者含义
gateway/.env否Settings设备映射、DashScope、OpenClaw、TLS、mDNS；没有它 Gateway 会在启动校验中失败。
provisioning/device-config.example.json模板可提交generate_nvs.py单台设备的 Wi‑Fi、device/gateway ID、token、根 CA 来源。
device-nvs.bin否generate_nvs.py每台设备独立秘密；生成器把权限设为 0600，烧录偏移 0x9000。
partitions.csv是ESP-IDF定义 NVS 0x9000 / 0x6000、固件、模型、存储等 Flash 布局。
local-device-config.h否generate_local_device_config.py编译期注入替代 NVS；只适用于受控本机开发，不应带到共享仓库。
MAP—J

第一次读源码的 90 分钟路线

目标不是读完，而是能准确画出并解释一次回合。

  1. 读 main/app_main.cpp，圈出创建的长期对象。
  2. 读 voice_controller.h，把字段归为硬件资源、会话、队列、任务、序号。
  3. 读 VoiceController::start()、run()，画出任务/队列关系。
  4. 读 start_listening()、capture_and_send()，确认按钮如何变成 SSM1 上行。
  5. 读 app.py::_authenticate_session()、_receive_audio()、_run_turn()，确认 Gateway 拒绝什么。
  6. 读 pipeline.py::process_turn()，确认 ASR/OpenClaw/TTS 的先后和失败输出。
  7. 最后读 legacy_movement_sequences.h 与网页 HTML；它们是动作内容，不是语音主链路。
