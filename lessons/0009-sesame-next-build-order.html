Sesame Robot · 开发路线

先闭环，再增强

下一目标不是“完成所有模块”，而是让一台真实 ESP32 在同一 Wi-Fi 下完成一次真实讲话、回答和播放。每次只替换一个 Demo，故障才可定位。

09—B

整个项目只遵守一个推进规则

每个阶段保持其他组件稳定，只让一个新变量进入系统。

错误做法： 真实 ESP32 + 真实 ASR + OpenClaw + 真实 TTS + 舵机 + OLED 一次接入 → 没有声音时，不知道故障在哪一层 正确做法： 已通过的闭环 → 替换一个 Demo → 给该边界做独立测试 → 做端到端回归 → 再替换下一个 Demo

你的第一条产品验收线

真人说一句中文 → ESP32 上传 → 电脑识别 → OpenClaw 回答 → 电脑合成语音 → ESP32 扬声器播出。

09—C

六个里程碑，严格按顺序

前一个阶段没有验收，不进入后一个阶段。

阶段要做什么完成条件
M0
电脑基线		 建立安全的 .env；固定启动命令；修复 OpenClaw actions 对象、超时和错误事件；创建无工具或最少工具的 Sesame 专用 Agent。 ESP32 模拟器在 openclaw 模式收到 asr.final → action/expression → tts.stop 和可解码 Opus。
M1
真机网络		 烧录 connectivity test；串口配置 Wi-Fi 与设备 token；访问 /healthz；完成 WebSocket 鉴权和 session.ready；再加入 mDNS。 拔插、重启、DHCP 地址变化后仍能自动重新找到电脑并连接。
M2
真实本地语音		 先在电脑上分别实现真实 LocalAsrProvider、LocalTtsProvider；从音频文件测试，不先接 ESP32。首版可用 sherpa-onnx 流式中文 ASR 和轻量中文 TTS。 本地 WAV/PCM 能得到正确中文；输入文字能生成可播放、格式严格为 16 kHz mono S16LE 的 PCM。
M3
ESP32 音频		 先做 I2S 麦克风上行，再做 I2S 扬声器下行；加入 20 ms 环形缓冲、Opus 编解码、sequence 和断线重连。 先证明录音可识别，再证明测试语音可播放；最后才合并双向链路。
M4
整机对话		 接入 VAD（语音活动检测）、会话状态机、队列、TTS generation、取消和打断；测量每段延迟。 连续 20 轮对话无死锁、串音、旧音频回放或 session 混淆。
M5
动作与安全		 把 OpenClaw 意图映射到固件白名单动作和 OLED 表情；加入 deadline、限位、急停和执行回执。 未知动作、过期动作和越界参数都被拒绝；语音失败不影响急停。
M6
产品化		 WSS、首次配对、token 轮换、日志脱敏、升级回滚、观测指标；启用 OpenClaw Sandbox 和最小工具策略；再评估多用户和跨 Wi-Fi。 通过断网、重启、错误凭据、恶意 JSON、模型超时和沙盒越权测试。
部署选择本课按你最初确定的“ASR/TTS 运行在电脑端”推进。如果当前唯一目标是最快展示，Provider 也允许临时换成云 ASR/TTS；但必须明确标记数据外发，不能把云端结果当成本地能力完成。
09—D

你现在立刻要做的三件事

不是六个阶段同时开工，只做当前最近的三个可验证结果。

Now 01

修完 OpenClaw 契约

让 actions 固定输出对象，给结构错误一次受限修复机会，失败则返回 agent.error，不能直接断设备 WebSocket。

Now 02

完成真机网络握手

重新连接 ESP32，烧录已经编译的连通性固件，取得 WIFI_CONNECTED / HTTP_HEALTH_OK / SESAME_WS_READY 三条实机证据。

Now 03

在电脑上实现真实 ASR/TTS

模型先只处理本地音频文件。ASR 和 TTS 各自通过独立 contract test 后，再替换 Pipeline 里的 Demo Provider。官方 sherpa-onnx 同时提供流式识别、中文模型和 TTS 运行能力，适合作为第一版统一运行时。

09—E

现在明确不做什么

这些都重要，但会让第一条真实闭环推迟。

暂不做： × 公网服务器和跨 Wi-Fi 中继 × 多用户云端部署和自动扩容 × 真正同时说和听的全双工 AEC × 大量 OpenClaw 工具、长期记忆和自动化 × 漂亮控制台、手机 App 和 OTA 平台 × 复杂舞蹈、丰富表情和全部舵机动作
安全例外在 OpenClaw 获得任何电脑工具权限之前，必须先设置工具 deny/allow 和 Sandbox。官方说明 Sandbox 决定工具在哪里运行，tool policy 决定工具是否可调用；两层不能互相替代。

09—G

一分钟自测

先自己回答，再展开答案。

为什么不是先做 ESP32 麦克风和扬声器？

因为 OpenClaw 契约和电脑真实 ASR/TTS 还没有稳定。先把电脑端变成可替换、可测试的稳定目标，ESP32 音频接入后才能明确定位问题。

沙盒应该什么时候做？

文本回答闭环可以先用无工具 Agent 验证；任何电脑工具对 OpenClaw 开放之前，必须完成 Sandbox 和工具白名单。

第一条真正有产品意义的验收线是什么？

一台真机在同一 Wi-Fi 下完成“真人讲话 → 本地识别 → OpenClaw 回答 → 本地合成 → 扬声器播放”。
