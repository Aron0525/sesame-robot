01 / DATA FLOW

一次对话，真实经过哪些部分？

音频与模型推理由电脑网关编排；ESP32 只做采集、播放、连接与最终动作校验。

BOOT第一次按下开始录音；第二次按下结束。
I2S 采集INMP441 → 16 kHz PCM → 20 ms 帧。
OpusESP32 编码为二进制音频包，不使用 Base64。
WSS带设备鉴权的加密 WebSocket 上行。
ASRGateway 通过 DashScope 将语音识别为文字。
OpenClaw仅收到文字与能力白名单，返回结构化计划。
TTS回复文字合成为 16 kHz PCM。
Opus 下行Gateway 重新编码，通过 WSS 回传。
播放 / 动作MAX98357A 播放；OLED 和舵机执行受限计划。
设备端电脑网关云端或本机 Agent
02 / IMPLEMENTED

目录里已经实现了什么？

点击筛选可分开看代码已实现、启动前需要配置，以及刻意禁止的能力边界。

ESP32 formal firmware已实现

硬件端语音与机器人控制

正式固件位于 firmware/esp32_voice_idf，不是 Arduino 草图的替代品。

  • INMP441 采集、MAX98357A 播放与 I2S 全双工
  • Opus 编解码、BOOT 录音状态机、WSS 会话
  • OLED 表情、8 路舵机 PWM、动作二次校验
  • 保留本地 HTTP 网页控制与舵机调试
Computer voice gateway已实现

电脑端的唯一编排器

FastAPI Gateway 位于 gateway，负责把各个组件串成一条受控链路。

  • WSS 设备鉴权、JSON/binary 协议和严格序号检查
  • Opus → PCM → ASR → Agent → TTS → Opus
  • 会话 TTL、打断、超时、OpenClaw abort 与有限重试
  • mDNS、TLS、设备单会话与状态审计
Local observability已实现

浏览器运行监控台

Gateway 运行后可打开 /dashboard，不是抓取终端窗口，而是读取网关直接产生的事件。

  • 设备 WSS 状态、turn_id、上下行 Opus 包数
  • ASR、OpenClaw、TTS 与动作计划的阶段时间线
  • 可选 USB 串口日志翻译；原始串口文本不保留
  • 默认隐藏 ASR 与回复文本，仅本机浏览器可访问
OpenClaw structured response已实现

模型输出不是自由文本，而是固定结构化计划

Gateway 只把 ASR 文字、短期 conversation_id 和设备能力列表发给本机 OpenClaw。模型必须返回版本化 JSON；不合规就终止该轮，不会调用 TTS 或驱动动作。

  • 表情白名单：idle、happy、sad、angry、surprised、sleepy、love、excited、confused、thinking
  • 模型动作白名单：stop、wave、rest、stand；每轮最多一个动作
  • Gateway 与 ESP32 均会再次校验表情、动作、时长、频率与机械安全
Speech providers需配置

真实 ASR 与 TTS

代码已接入 DashScope 的实时 ASR 与 TTS，但必须在电脑私有 .env 中配置凭据并显式同意云端语音处理。

  • ASR：fun-asr-realtime
  • TTS：qwen-audio-3.0-tts-flash
  • 可选合规的授权音色注册
  • 当前 TTS 会收齐 PCM 再编码下发，不是边生成边播放
OpenClaw runtime需配置

本机 Agent 与 Workspace

项目已包含 OpenClaw 安装入口和固定协议；实际运行仍依赖本机 daemon、token、Agent 与 workspace 配置。

  • 默认只允许回环地址 127.0.0.1:18789
  • 按 conversation 派生 session key，而非暴露用户身份
  • 需要为真实业务逐项批准工具，而不是默认开放
Field deployment需配置

设备接入与网页控制

每台设备都需要私有 NVS：Wi‑Fi、DeviceID、设备 token 和网关根证书不写入源码。

  • mDNS 用于发现，TLS 身份和设备 token 用于认证
  • 需同一非访客 Wi‑Fi/VLAN，允许 mDNS 与客户端互访
  • 接好 INMP441、MAX98357A、OLED 与独立舵机供电
privacy by default刻意限制

默认不保存原始音频

PCM/Opus 默认只在内存中存在。日志与监控台只保留时间、包数、状态与动作/表情 ID。

  • OpenClaw 不接收原始音频、设备 token 或 Wi‑Fi 密码
  • 云端 ASR/TTS 必须显式设置允许，不能静默回退
  • 调试文本默认隐藏，需本机短时开启
physical safety刻意限制

模型不能直接控制舵机

模型只能选择有限意图；不能下发 8 路舵机角度，也不能绕过 Gateway 和 ESP32 的安全检查。

  • 单轮至多一个白名单动作
  • 动作时长限制 100–5000 ms
  • 设备端保留急停和机械限位校验
03 / WHAT IT CAN DO

现在可用来做什么？

它已经是一个能验证核心产品体验的垂直 MVP，而不是只有一堆独立模块。

三类立即可做的场景

语音陪伴与问答按 BOOT 说话，机器人用 TTS 回复，同时选择情绪表情。
语音触发的有限动作例如“挥挥手”，OpenClaw 返回 wave，Gateway 和 ESP32 再完成安全校验。
机器人调试与演示浏览器查看链路每一段耗时，或通过 ESP32 原网页进行舵机、动作和表情测试。
私有化 Agent 的原型将 OpenClaw 作为受限的本机 Agent 层，后续可逐项增加业务工具。

04 / HONEST BOUNDARIES

当前不能假装已经完成的部分

这三项不是缺代码，而是需要真实部署条件或下一阶段产品决策。

端到端体验取决于现场网络

ESP32 必须看得到 2.4 GHz Wi‑Fi，并能与电脑 Gateway 在非访客网络内进行 mDNS/TCP/WSS 通信。路由器 AP 隔离会阻断网页和直连访问。

云端语音仍有隐私与成本边界

DashScope 启用后，当前轮音频或待合成文字会离开电脑。需要用户同意、费用控制和数据保留策略，不能把“云端可用”等同于“完全本地”。

Agent 工具应从零权限开始

OpenClaw 目前适合负责结构化回复与场景扩展。接入任何真实工具前，应使用独立 workspace / sandbox，并逐项白名单批准，而不是给模型终端或文件系统权限。
